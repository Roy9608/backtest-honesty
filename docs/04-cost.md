# 铁律 4：成本必须实测，且分清进出方式

**费率不能只问一个数字，必须问清「开仓 / 平仓各用什么单」。**

## 为什么

这是最容易被"想当然"掉的一环，因为它看起来是个已知数。

| 下单方式 | 典型费率 | 滑点 |
|---|---|---|
| 挂单 maker | 通常 0.02% | 无 |
| 吃单 taker | 通常 0.05% | 有（约 1bp） |

**常见错误**：假设"双向 taker" → 算 12bp。
**实际情况**可能是 maker 进 / taker 出 → 只有 8bp。

> **高估 4bp，足以让一个薄利策略从正变负。**

## 同一类错误的三种变体（都真实发生过）

| 变体 | 表现 |
|---|---|
| **假设值 ≠ 实测值** | 假设 2.8bps，实测 3.96bps |
| **进出方式搞错** | 假设双向 taker，实为 maker 进 |
| **新旧口径混用** | 同一项目里，前期用 12bp、后期用 8bp，跨阶段对比时混淆 |

**建议**：把费率写成代码里的**单一常量**，并在报告里显式打印出来。
不要在不同脚本里各写一份。

## α 与成本的直接对比（必做）

```
α（真实超额） = 策略收益 − β基准

若 α < 成本  →  无论参数怎么调都不成立
```

**这是最后一道闸门。** 前面算得再漂亮，这一步不过，结论就是"不成立"。

## 成本必须在报告里显式出现

很多回测报告只报毛收益，或者在附录里提一句成本。
**这会导致读者无法判断 α 是否覆盖成本。**

强制要求：

```markdown
| 项 | 值 |
|---|---|
| 毛收益 | +X.XX% |
| 单笔成本 | X.XXX% |
| **α vs 成本** | ✅ 超过 / ❌ 未超过 |
```

## 一句话

> **成本不是"最后扣一下"的数，它是判据的一部分。**
